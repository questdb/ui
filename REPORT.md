## Summary

**Verdict: request changes.** Six Critical findings, four of which hit users who take no unusual action at all — one fires on first page load after upgrade, one on the first screen a new user sees.

The design is a genuine improvement and most of the machinery is sound: the listing plumbing, the label derivation, the collapse of the `@key=value` model-string format, and the settings round-trip are all correct, idempotent, and well covered by the 49 new unit tests. The problems cluster in three places.

**The headline feature does not work.** `reasoningEffort` and `reasoningModels` are written by unrelated code paths but `reasoningOptions()` requires both (#1). `reconcileSettings` — the PR's own migration — produces exactly the broken combination, persists it on boot, and the Settings dropdown then reads "High" back forever. Users who had "GPT-5.4 (High Reasoning)" on `main` are silently downgraded with no signal, and the PR deleted the "Extended thinking model enabled" banner that would have contradicted the UI. `settings.test.ts:63-80` asserts the fold and never checks the companion field, so the suite certifies the bug. Separately, roughly 60 lines of the new reasoning code in the chat-completions provider can never execute (#36).

**Removing the static allow-list removed a load-bearing guard.** `MODEL_OPTIONS` was not just a menu — it constrained what could reach `enabledModels`. Without it: OpenAI fine-tune ids parse as a phantom `ft` provider and throw `Unknown provider: ft` on every message (#2); older Claude models become one-click-enableable and 400 on every request against the hardcoded `max_tokens: 64_000` (#4); and disabling your selected model can silently move you to a different vendor (#35). Each was impossible before this PR.

**The picker loses user data quietly.** The sub-modal's "Save" only writes React state, so closing Settings discards everything — while the identical button on the custom-provider path persists immediately (#3). Manual model entry self-destructs on the next open and blames the provider (#34). "Deselect All" leaves hidden-but-enabled models enabled and Save persists them (#7). Unavailable rows have no checkbox, so any false negative from the asymmetric `matchesListedModel` is unrecoverable (#8).

**Regressions and tradeoffs worth calling out explicitly:** chat titles and context compaction now run on the user's most expensive model for every upgraded user (#38) — the PR added `getUtilityModel` for exactly this and wired it into titles but not compaction; `@reasoning=low` users are silently moved to the model default with no Low option to return to (#14); Anthropic `temperature: 0.3` is dropped for models that still accept it, changing SQL-generation determinism (#15); and rolling back to the previous release destroys `enabledModels` irreversibly (#13).

**Quality gate:** `yarn typecheck`, `yarn lint`, `yarn test:unit` (2051 tests) and `yarn build` all pass, so no rows in the table come from that step. Note that `react-hooks/exhaustive-deps` is disabled repo-wide, so none of the hook findings had a CI backstop, and the `Running Tests With Context Path` job — the direct check for #5 — was still in progress at review time.

**Counts:** 38 findings verified (6 Critical, 25 Moderate, 7 Minor); 23 draft findings dropped as false positives. 36 in-diff, 2 out-of-diff (`anthropicProvider.ts`'s `max_tokens` ceiling, and the `LocalStorageProvider` rollback path), plus #2, whose failure surfaces in `registry.ts`/`executeAIFlow.ts`. The low out-of-diff count is a real result rather than an underrun: the cross-context pass walked ~15 consumer callsites — `AIStatusProvider`, `AIChatWindow`, `ModelDropdown`, `AIConversationProvider`, `CustomProviderModal`, and every `StoreKey.AI_ASSISTANT_SETTINGS` reader — and returned evidenced SAFE verdicts for them, with the label change coming out as cosmetic drift only.

**Smallest set of changes that would unblock this:** fix the `reasoningEffort`/`reasoningModels` coupling (#1), reject colon-containing ids from built-in listings (#2), make the sub-modal Save persist or relabel it (#3), clamp `max_tokens` per model (#4), revert the `e2e/commands.js` baseUrl line (#5), render step 2's validation error (#6), and add `registry.test.ts` plus an Anthropic `temperature` regression guard (#25).
