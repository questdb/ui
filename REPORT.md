**`refactor: redesign notebook cell dimensions and responsive views`**

---

## Verdict

**Request changes.** 30 findings verified, 14 draft findings dropped as false positives. 26 in-diff, 4 out-of-diff.

The refactor's central move — making `paneView` viewport-independent — is sound in principle, but it creates a cell state that could not previously exist: **a cell that has a result while rendering editor-only in a wide tier.** Four separate confirmed defects fall out of that one state, and one of them destroys user data with no confirmation. A second cluster comes from the three new grid-height functions disagreeing with each other, which breaks react-grid-layout's `minH ≤ h ≤ maxH` contract for a common cell shape.

All four quality gates pass (typecheck, lint, 2073 unit tests, production build), so none of this is caught by CI.

## PR title and description

The title uses `refactor:`, but this change removes an MCP tool (`set_cell_view_maximized`), re-types a persisted cell field (`isViewMaximized: boolean` → `paneView: enum`), renames a telemetry event, removes `grid.h` from the agent wire contract, and changes user-visible controls. That is not a refactor — it needs `feat!:` or an explicit breaking-change note.

The description does not repeat the verb (good), but it is written entirely in implementation terms. It never states the end-user impact: that "Split view / Maximized view" becomes a "Show editor / Hide editor" toggle, that chart zoom now keys off measured width instead of row count (removing wheel-zoom from mid-size charts **including the main Result panel**), or that persisted `isViewMaximized` is migrated read-time with no Dexie version bump.

## Summary

**Request changes.**

**30 findings verified, 14 draft findings dropped as false positives.** Split: **26 in-diff, 4 out-of-diff** (`ResultChart` losing wheel-zoom, `importTabs` leaking markdown sub-state, the MCP version gap, and the snapshot round-trip resizing legacy cells).

**Regressions.** Eight of the nine highest-severity findings are regressions rather than pre-existing bugs, and each was confirmed against `origin/main`:

- Making `paneView` viewport-independent creates *"has a result, renders editor-only in a wide tier"* — a state the old tier-coupled `isViewMaximized` made structurally impossible. Issues **1** (destroys the result and its snapshot), **4** (draw mode with no chart), **9** (83% blank on maximize) and **26** all originate there. Issue 1 is the one to fix first: it is reachable from the UI with no agent involved, it deletes the IndexedDB snapshot, and the affordance actively invites the click.
- The three new grid-height functions disagree (**issue 2**). Base inverted `minH > h` only below ~120px of editor; the new `Math.max(minTopHeightFor, topHeight)` term makes it unconditional for every split cell whose result is a 44px status notification — that is, every `CREATE TABLE`, `INSERT` or failed query.
- The `typeof === "boolean"` guard that kept the old `is_view_maximized` field safe at the snapshot boundary was removed with the field (**issue 3**), leaving an unvalidated agent-controlled string interpolated raw into the prompt.
- Chart zoom moved from row-count to measured width (**issues 8** and **21**), which makes the ECharts remount key width-dependent and silently removes wheel-zoom from mid-size charts on a surface the PR does not mention.

**Tradeoffs.** Two are deliberate and defensible but under-documented: the density-based zoom gate is better-reasoned than a flat 200-row threshold yet drops `{type:"inside"}` along with the slider, and `MIN_CHART_HEIGHT_PX` gives charts a sensible floor but applies it retroactively at render instead of migrating. Both need a line in the description at minimum.

**Deferring the MCP bump does not work as intended** (**issue 7**). Because `isBridgeVersionMismatch` requires exact semver equality and `EXPECTED_MCP_VERSION` is unchanged, the server version the console itself tells users to install pairs with no warning — and then silently reports success for resize operations that do nothing. Either bump it here or add explicit retired-tool errors.

**What CI cannot tell you.** Typecheck, lint, 2073 unit tests and the build all pass. The `cells/` directory has no tests at all, no e2e spec touches the changed controls, and one existing test actively locks in issue 23. The cheapest high-value additions are the `minH ≤ h ≤ maxH` invariant test and an e2e spec for hide/show editor — between them they would have caught issues 2, 14 and 1.
